# LOG-005 — Backend API Layer

- **Date:** 2026-09-23
- **Change type:** `feature` (HTTP/API layer over the LOG-004 domain)
- **Status:** Implemented and verified (uncommitted working tree on `feature/backend-api-layer`)
- **Scope:** Thin controllers + Form Requests + API Resources + routes + Sanctum auth + `EnsureAdmin` + error renderers + Redis rate limiters + API feature tests. No migrations, no domain changes, no README/`.env`/frontend changes.

## Summary

Exposed the existing booking domain over `/api/v1` without moving any business logic into controllers: property-scoped catalog reads, UUID-based availability, guest checkout (booking_code + guest_email, mismatch → 404), payment initiate/process with header-wins idempotency, Sanctum register/login/logout, owner-scoped `/my/reservations` (status filter, 15/page), and a minimal admin surface (reservations read/confirm/cancel, blocks index/store/destroy). Controllers validate shape via Form Requests, delegate to LOG-004 Actions, and return Resources. `GET /api/user`, `GET /v1/health`, `POST /v1/probe/validation` preserved; `/v1/me` upgraded to `UserResource`.

## Authentication / Authorization

- Sanctum personal-access tokens; expiration null (per order).
- Register hardcodes `role = guest`; `role` absent from every Request class.
- Null-password guest-checkout rows fail login with the generic message (no enumeration delta).
- Guest scope = booking_code (URL) + guest_email (validated per request); mismatch → 404.
- Customer lists scope `user_id = auth()->id()`; cross-user → 404.
- `EnsureAdmin` (`auth()->user()->role === UserRole::Admin`) → `abort(403)`; first enforcement point of `UserRole`.

## Validation / Domain Boundary

- Requests validate shape only (uuid/email/date_format/`after`/integer/enum-in/unique/pagination). `ProcessPaymentRequest` applies `prohibited` to `scenario` in production.
- Controllers pass `validated()` (+ header idempotency key) to Actions; map nothing except 404 ownership checks.
- All invariants (overlap, capacity, active-cabin, state legality, pricing, expiry, idempotent reuse, EXCLUDE→409) remain in LOG-004 Actions/domain. `InvalidArgumentException` from the domain renders as 422 with the domain message.

## Error Contract

- 422 validation `{message, errors}` (unchanged); 422 domain `{message}` (new: `InvalidArgumentException`).
- 401 `{message: Unauthenticated.}` (unchanged); 403 `{message: Forbidden.}` (new: `AuthorizationException` + exact-class `HttpException` from `abort()`).
- 404 `{message: Not Found.}` (unchanged; also used for ownership mismatches).
- 409 `{message: BOOKING_CONFLICT}` (unchanged; exception + raw exclusion).
- 429 Laravel default via throttle (status preserved by new `HttpExceptionInterface` branch).
- 500 `{message: Server Error.}` sanitized fallback (new); framework `HttpException` statuses preserved.

## Important Decisions

1. **Limiter keys namespaced** (`api:IP` etc.) — the Redis throttle middleware uses `$limit->key` verbatim, so unprefixed keys would collapse all three windows into one.
2. **`HttpException` exact-class branch** returns its message (safe: `abort()` messages are author-controlled); other `HttpExceptionInterface` statuses preserved with a generic body so 429/405 survive the sanitizer.
3. **Test-only Redis clearing** in base `TestCase::tearDown` (md5-hashed limiter keys) — counters survive `RefreshDatabase`; without it the suite 429s itself.
4. **409-overlap assertion placed last** in the blocks test — `RefreshDatabase` wraps each test in one transaction and the EXCLUDE violation aborts it (production unaffected: no wrapping transaction there).
5. **Logout test calls `auth()->forgetGuards()`** — same app instance serves all calls in one test, so the guard-cached user must be dropped before re-probing the deleted token (test-harness only).
6. **Production-scenario test uses `app()->detectEnvironment()`** — `environment()` reads the boot-time binding, not live config.
7. **`PUT/PATCH` on blocks asserts 405** — Laravel returns 405 (not 404) for wrong-method on an existing URI; confirms no update route exists.
