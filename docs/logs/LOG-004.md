- **Date:** 2026-09-23

No schema changes (price total = subtotal, single cabin). No frontend, no controllers/resources. No README changes.

## Summary

Built the reservation lifecycle on top of the LOG-003 domain schema: guest checkout (find-or-create by normalized email, no overwrite, password null, no tokens), cabin lock + in-tx availability re-check + EXCLUDE as final guard mapped to HTTP 409 `BOOKING_CONFLICT`, price snapshot (`total = subtotal`), 15-minute payment window (`CreateReservationAction::PAYMENT_WINDOW_MINUTES`), sandbox payment simulation (success/fail/timeout) with gateway outside the transaction, success chaining `pending_payment → paid → confirmed` through the state machines, failure leaving the reservation pending, timeout parking payment as `unknown`, idempotent retry via open-payment reuse (client key opaque in metadata, `provider_reference` as internal attempt identity + DB backstop), cancel/confirm, and per-row expiry with lock + re-check driven by a per-minute skip-locked sweep.

## Domain / State Changes

- Reservation lifecycle enforced in code: `pending_payment → paid/expired/cancelled`, `paid → confirmed/cancelled`, `confirmed → cancelled`.
- Payment lifecycle enforced in code: `pending → processing/expired`, `processing → paid/failed/unknown/expired`, `unknown → paid/failed/expired`, `failed → processing`.
- Guest claim deferred to auth phase (user row created with null password, `guest` role; no tokens issued) — documented here per order.

## Important Decisions

1. **`→expired` extension on payments.** Backend AGENTS.md payment map has no expiry edge; the expire action must close open payments, so `pending/processing/unknown → expired` added and documented here.
2. **Gateway outside the transaction.** `ProcessPaymentAction` commits `→processing`, charges, then reconciles — no holding DB locks during the (simulated) provider call.
3. **Success auto-confirms.** Payment success runs `pending_payment → paid → confirmed` via `ReservationStateMachine` (so `payment_succeeded` + `confirmed` events both land); `ConfirmReservationAction` covers manual/admin flows.
4. **`Str::createRandomStringsUsing` for the booking-code test.** Deterministic collision without touching production code.
5. **`lock('for update skip locked')` passthrough.** PG grammar returns the raw string, so the job sweep is valid Postgres.
