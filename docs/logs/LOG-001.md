## Summary

Added a reproducible Docker Compose development environment for the Villa Dieng Booking Engine: PostgreSQL 15 (with required extensions), Redis 7, a PHP 8.4 Laravel development runtime, and a Node 24 Vite development runtime. All four services boot, pass health checks, and were verified end to end (Laravel 200 on `/`, PostgreSQL extensions present, Redis PONG, Vite 200 on `/`).

| `redis` | `redis:7-alpine` | 6379 | Named volume `redisdata`; healthcheck via `redis-cli ping` |

Ports, database name, user, and password are overridable via the root `.env.example` variables (`POSTGRES_*`, `REDIS_PORT`, `BACKEND_PORT`, `FRONTEND_PORT`).

## Important Technical Decisions

1. **PHP 8.4 runtime despite `composer.json` claiming `^8.3`:** the committed lockfile requires PHP `>= 8.4.1` for some dependencies, and `composer install` refused on PHP 8.3. The Dockerfile uses `php:8.4-cli`. Follow-up: align `composer.json`'s `php` constraint with the lockfile.
2. **`--no-reload` on `artisan serve`:** Laravel's `serve` spawns the `php -S` worker with only a small passthrough env list unless `--no-reload` is given, so the worker ignored Compose-provided `DB_*`/`REDIS_*` and fell back to the bind-mounted host `backend/.env` (wrong host, typo'd db name) → HTTP 500. `--no-reload` runs the server in-process so container env applies. Verified via `/proc` environ comparison before/after.
3. **No API proxy in Vite config:** `frontend/src` contains no backend API client yet; only `server.host`/`port` were added. Add a `/api` proxy when the frontend actually calls the backend.
4. **Dev-only credentials in committed files are placeholders** (`villa_dieng_dev`); real secrets live in untracked `.env` files only.
5. **Pre-existing host `backend/.env` was not modified** (points at `127.0.0.1` with a typo'd db name `db_villa_diend`). It is bind-mounted for dev convenience but is shadowed inside the container by Compose env for the server process. It should be brought in line with Docker values separately.
