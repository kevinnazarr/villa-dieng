# LOG-006 — Frontend Localization Shell (ID/EN)

- **Date:** 2026-09-23
- **Change type:** `feature` (frontend foundation: ID/EN localization shell)
- **Status:** Implemented and verified (uncommitted working tree on `feature/frontend-foundation`)
- **Scope:** Zero-dependency locale model + typed dictionaries + `LocaleContext` + `Intl` format helpers + keyboard-accessible switcher + shared-UI wiring + `LOG-006.md`. No backend, migration, README, Docker, or dependency changes.

## Summary

Established the frontend localization foundation later pages consume: `Locale` (`'id' | 'en'`, default `'id'` matching the backend `users.locale` default and domestic-primary audience), compile-time dictionary completeness (`id: Record<TranslationKey, string>` where `TranslationKey = keyof typeof en`), `LocaleProvider` + `useLocale()` mirroring the `AuthContext` pattern, thin `Intl` wrappers (`id-ID`/`en-US`), and a native-button `LocaleSwitcher` in all three layouts. Shared chrome copy (layouts, guards loading/error, Login/Register labels/buttons, NotFound/Forbidden/Placeholder/Home) now renders via `t()`; server-originated strings (`ApiError` messages, validation bags) stay verbatim. `<html lang>` syncs for assistive tech. `PlaceholderPage` takes `titleKey` so the static route table stays localizable.

## Important Technical Decisions

1. **Default `id`** — matches backend `users.locale DEFAULT 'id'` and the domestic-primary audience; `en-US`/`id-ID` Intl mappings fixed per approved plan.
2. **EN as key source of truth** — `TranslationKey = keyof typeof en` + `id: Record<TranslationKey, string>` makes missing Indonesian keys a build error (`tsc` gate), not a runtime surprise; runtime fallback chain `locale → en → key` is defensive only.
3. **`titleKey` prop (not `title`)** — route objects are static so they cannot call the `t()` hook; translating inside `PlaceholderPage` keeps the centralized table localizable with a one-word diff per route.
4. **No backend locale sync** — no endpoint accepts a locale preference (`User.locale` is a server-side column, not a preference API); syncing would invent a contract. Documented to prevent future confusion.
5. **Server strings stay verbatim** — backend has no localized validation; translating `ApiError` client-side would diverge from API truth. Mixed-language forms are a known limitation.
6. **localStorage over URL prefix** — a `/id/...` prefix would multiply every route + guard `from` handling for a shell commit; same guarded-`storage()` pattern as `token.ts`.
