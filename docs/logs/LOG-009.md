## Summary

Turned `/booking` into a working two-phase flow: (1) property→cabin selects, native date/guest inputs, explicit availability check bound to an input snapshot; (2) guest-details form unlocking only on a fresh `available` result, then reservation POST with per-attempt `crypto.randomUUID()` idempotency key and an inline confirmation (code + email + server total + next steps). Stays on `/booking`; no navigation to `/booking/success`, no payment UI.

## API Contracts Used

- `GET /api/v1/availability?cabin_id=&check_in=&check_out=` → `{data: {cabin_id, check_in, check_out, available}}`; 422 on bad UUID/dates. Blocking = `pending_payment/paid/confirmed` overlap `[)` + availability blocks.
- `POST /api/v1/reservations` → 201 `ReservationResource` (`booking_code VD-XXXXXXXX`, `pending_payment`, price snapshot, payments/events loaded). 409 `{message: BOOKING_CONFLICT}` on overlap/exclusion/inactive; 422 validation + domain; `throttle:booking` 30/min/IP. Guest find-or-create by email (null password, never loggable-in).
- Shapes consumed 1:1 from existing `types/api.ts` (`AvailabilityResult`, `Reservation`, `DataEnvelope`); no type changes.

## Important Technical Decisions

1. **Cabin URL contract** — `/booking?property=<slug>&cabin=<slug>` reuses catalog slug scheme (never UUIDs); resolved via active catalog; invalid slugs → inline warning, page stays usable, never a global 404.
2. **Explicit check, snapshot-bound submit** — no auto-fetch (throttleniosk); result stores exact inputs; any change resets to `idle`; submit requires `snapshotMatches`, so stale availability can never arm the POST.
3. **Idempotency per attempt** — `crypto.randomUUID()` generated inside submit handler only; passed via existing `idempotencyKey` option; no auto-retry anywhere.
4. **Inline confirmation, no success page** — locked decision: stay on `/booking`, show code + email + server `total` + next steps + Home link. No email in URL, no payment claims (`pending_payment` explicit).
5. **Native date transport** — `Y-m-d` strings compared lexically (`out <= in` invalid); `todayLocal()` from local parts (no `toISOString` UTC shift); `min` attrs mirror the rules.
6. **Estimate honesty** — summary shows cabin `base_price` labeled informational; final total only from the 201 response.
7. **Conflict recovery** — 409 via `isBookingConflict` → localized conflict state, availability reset to `idle`, guest details preserved, user re-checks explicitly.
