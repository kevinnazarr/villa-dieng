## Error Envelope

`backend/bootstrap/app.php` renders JSON for `api/*` (or `expectsJson`) requests:

- `ValidationException` → `{message, errors}` with validator status
- `NotFoundHttpException` → `{message: "Not Found."}` 404
- `AuthenticationException` → `{message: "Unauthenticated."}` 401
- Everything else falls through to Laravel defaults (debug pages in local, generic 500s in production). No 409 mapping yet — future domain conflicts hook in here.

## Important Decisions

1. **UUID users now, not later.** Approved Phase 2 decision. Migrating the PK before any domain tables exist (no FKs to rewrite yet) is the cheapest point; sessions + Sanctum morphs updated in the same change.
2. **Sanctum foundation only.** `HasApiTokens` + token table aligned to UUIDs; no login/register/password-reset flows — those belong to a future auth phase.
3. **`php ^8.4` minimal fix.** The lockfile already required `>=8.4.1` and Docker runs PHP 8.4; only the `composer.json` constraint lied. One-line change + lock hash refresh, no dependency upgrades. Note: this drops nominal PHP 8.3 support claimed by the skeleton — if 8.3 compat matters, the lockfile must be regenerated on 8.3 instead.
4. **phpunit `<server>` mirrors required, twice.** Root cause (verified via `$_SERVER` dump and Laravel's `ServerConstAdapter`): Compose injects `DB_*` into the real process environment; PHPUnit `<env>` writes `putenv`/`$_ENV`, which Laravel reads only after `$_SERVER`. So `force="true"` alone fixed nothing until `<server>` mirrors were added. Same mechanism bit `CACHE_STORE`/`QUEUE_CONNECTION`/`SESSION_DRIVER` (stock ExampleTest 500'd with "no such table: sessions") — all three now forced to `array`/`sync` with mirrors.
5. **Health endpoint returns 503 degraded, not 200-always.** Lets compose/k8s healthchecks distinguish "app up, dependency down" from fully ready.
