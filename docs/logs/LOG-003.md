## Summary

Built the booking-engine domain layer on top of the LOG-002 backend foundation: PostgreSQL native enums, UUID-keyed tables with `NUMERIC(12,2)` money / `DATE` stays / `CITEXT` emails / `JSONB` metadata, GiST `EXCLUDE` overlap guards on reservations (partial, blocking statuses only) and availability blocks (full), append-only reservation events, and a PG-backed integration suite proving the §7 DB design on real PostgreSQL. Full suite: 20 passed, 33 assertions (11 PG domain + 9 foundation).

## Important Decisions

1. **Dead-hook diagnosis → `refreshApplication` override.** `PgTestCase` first used Testbench's `getEnvironmentSetUp()`, which Laravel's foundation `TestCase` never calls (zero callers in framework) — the suite silently ran on sqlite and 4 tests failed. Override sets `DB_CONNECTION` before app boot instead.
2. **Idempotent enum migration.** `migrate:fresh` drops tables but not types; a partial run left stale types behind, so 000101 uses `DO $$ ... EXCEPTION WHEN duplicate_object`.
3. **Enum-conversion ordering (108/110).** Column `DEFAULT`s and partial-index predicates referencing the old type block `ALTER TYPE ... USING`: drop default → drop partial index → convert → re-set typed default → re-create index.
4. **`expires_at` in factory.** `chk_reservation_expiry` requires pending rows to carry `expires_at`; the factory sets `now()->addHour()`.
5. **`created_by` required on blocks.** Migration 000111 makes it NOT NULL; the test creates an actor user explicitly.
